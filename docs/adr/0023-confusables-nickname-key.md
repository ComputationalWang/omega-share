# ADR 0023 — Nickname key: UTS #39 skeleton, server-only table

**Status:** accepted (2026-10-01) · contract [OME-279](/OME/issues/OME-279) · plan [OME-270](/OME/issues/OME-270) · threat model `docs/research/m3-threat-model.md` §10 "Full confusables" · builds on ADR 0016

**Context:** ADR 0016 (M3) made nicknames NFKC, single-script (Latin never mixes with Cyrillic, Greek, Armenian, Cherokee) and unique per room by a case-, width- and accent-insensitive key. It accepted two gaps for M4: whole-script twins ("сосо" in Cyrillic next to Latin "coco") and digit/letter lookalikes ("A1ice", "B0b"). UTS #39 §4 closes both with the *skeleton* (NFD, then each code point replaced by its prototype from `confusables.txt`, then NFD). The table is about 100 KB, and the web app must not pay for it.

## Decision

1. **Server-only entry.** `@omega/shared/confusables` (`packages/shared/src/confusables.ts`) exports `skeleton(s)` (plain TR39), `nicknameKey(nickname)` and `CONFUSABLES_VERSION`. The main entry `@omega/shared` does not import it, so the web bundle does not change (measured: all 15 web JS chunks are byte-identical, delta **0 B**). A contract test bundles both entries and checks the table is only in the second one.
2. **The key.** `nicknameKey` = lowercase → skeleton → lowercase → skeleton → remove combining marks. One exception in the first pass: a capital whose prototype has no capital (TR39 maps "I", Cyrillic "І" and "Ӏ" → "l") is lowercased before it is mapped. Without the exception, "ALICE" would become "allce" and stop colliding with "Alice". Without the first skeleton, lowercasing would lose Greek "ΤΟΜ" vs "TOM" ("τ" → "ᴛ"). Case-insensitivity (the M3 guarantee) wins: "AIice" (capital I) is "aiice", not "alice". "A1ice" still collides.
3. **Table.** `src/confusables-table.ts` is generated by `bun run --filter @omega/shared gen:confusables` (`packages/shared/scripts/gen-confusables.ts`) from `https://www.unicode.org/Public/18.0.0/security/confusables.txt`, pinned by sha256. Only sources a nickname can hold (`[\p{L}\p{N}\p{M}_.\- ]`) are kept: 5212 entries, 82 KB minified (23 KB gzip) in the server bundle. It is parsed into a `Map` on the first call (about 2 ms), and a key then costs about 1.3 µs. Joins are rare, so this is not a hot path.
4. **Licence.** `confusables.txt` is data under the Unicode licence (https://www.unicode.org/license.txt), a permissive licence compatible with AGPL-3.0-only. The generated file says where it came from.
5. **Rollout.** The M3 `nicknameKey` in `@omega/shared` stays until the server imports the new one (a Server Engineer sub-issue of OME-279). It is then removed in a later contract change.

## Consequences

- TR39 collisions are deliberate and sometimes surprising: "m" ↔ "rn" means "Amie" and "Arnie" collide, as do "Bob" and "B0b". Members get `nickname_taken` and pick another name. That is the cheap side of the trade.
- Bun's NFD is Unicode 17.0 and the table is 18.0. Letters that are new in 18.0 may not decompose as 18.0 says. That is harmless for a uniqueness key, because both names go through the same function.
- A Unicode upgrade changes keys. Keys only live in a room's memory (they are recomputed on join), so an upgrade is a regenerate-and-redeploy: bump `VERSION` and `SHA256` in the generator together.
- Not covered: confusables across word boundaries or spaces ("rn" vs "r n" stay distinct), and names that differ only by a confusable the nickname schema already rejects.
