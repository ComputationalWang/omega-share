### Why a new tunnel-lane spec

Regular e2e runs through Vite dev, which never serves the server's HTML, headers, 404s or share card (harness-gotchas, OME-273). `e2e/tunnel-m9-site.e2e.ts` therefore builds the site and serves it from the real server process (`STATIC_DIR`), behind the local TLS proxy, on its own lane:
- Ports: proxy `TUNNEL_PORTS.proxy + 8`, server `TUNNEL_PORTS.server + 81`.
- Rooms are seeded into a temp DB through the store's own parse.
- The taken-down room uses the real operator takedown over the admin socket.

The unit tests in `apps/server/test/site.test.ts` stay the fast check. This spec proves the same behaviour end to end, in Chromium and in a raw crawler fetch.
