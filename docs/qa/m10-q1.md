### Abuse cases (`e2e/m10-abuse.e2e.ts`, new)

The wire cases start a server of their own (`PORTS.server + 10`, `TRUST_PROXY=loopback`, `RESUME_GRACE_MS` 6 s) so per-address limits apply. The browser cases own a server and a Vite site.

| Case | Result |
|---|---|
| Forged resume token (right shape but random, garbage, wrong length, another room's valid token): a fresh member, never someone else's seat or member id; the seat holder isn't displaced | pass |
| Token replayed after an explicit leave: dead, with the same answer as a forgery | pass |
| Token replayed after the grace window: dead; one leave line; the seat is free | pass |
| One token on two sockets at once (raw race): one member, one live socket, the other closed as replaced | pass |
| The resume token is never in any frame a peer receives, nor in the server log | pass |
| `POST /rooms` with an unknown preset (`unknown`, `Classic`, `""`, `../classic`, `null`, `{}`, `0`, a 10 kB string): 400 `invalid_body`, no room, no echo of the input | pass |
| A body over `MAX_CREATE_BODY_BYTES`, declared or chunked: 413, no room | pass |
| Owner `layout-set`: oversized, malformed or out of range is refused, and the room's layout is unchanged | pass |
| Saved layouts in `localStorage`. Cases: more than 5 entries; a 1 MB entry (20 000 pieces); a 1 MB name; a 1 MB junk key; 100 000-level nesting; nested junk in an entry; out-of-range or unknown furniture and tiles; unknown keys; `__proto__` keys; a top-level `__proto__` object; duplicate names. Each time: home renders, the picker lists only valid entries (at most 5), a room can be created, nothing invalid reaches the server (unknown keys are stripped) | pass (12 cases) |
| A saved entry deleted behind the picker's back is refused, not sent | pass |

**Rate limits and rejected bodies (asked in the brief):**
- A rejected create body (400 or 413) costs its key one of the 2 creates per 10 min, because `apps/server/src/http.ts` takes the `creates` token before reading the body.
- It never costs the server-wide bucket: 12 rejections from 12 keys still leave valid creates at 201.
- The wrong content type (415) costs nothing.

This is defensive and fine against abuse. The site validates before posting, so a real user doesn't hit it. Noted, not filed.

## Watch items (not blockers)

1. **Landing transfer grew 24.4 KB (+51 %)**, to 72.6 KB of 120 KB. The cause is the preset picker on `/`:
   - its thumbnails (image bytes 27.0 KB)
   - the `preset-thumbs`, `saved-layouts` and `pending-layout` chunks, which load eagerly on `/`

   It is within budget and LCP didn't move. If the landing grows again, lazy-load the thumbnails when the create form scrolls into view.
2. **A rejected `POST /rooms` body spends the per-key create allowance** (see above). Keep it in mind if a client ever posts unvalidated input.
