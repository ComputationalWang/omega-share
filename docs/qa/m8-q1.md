## e2e

- Full `bun run e2e` (e2e, e2e-sync, e2e-tunnel) on `fbb5860`, twice: **293 passed, 0 failed, 0 flaky** both times (4.5 min each, load 2 and 10).
- `bun run check`: 4856 pass, 1 skip, 0 fail.

Earlier runs found two test-side problems and one product bug. All are fixed or pinned:
- **Tier probe under load (test).** The probe runs once per room start. In the 8-worker run, with the trace screencast on, it settled in Basic, which is honest (ADR 0017: tracing drops vsyncs). The walk-tier spec now runs with `trace: "off"`, and `reachSmooth` allows up to three room starts.
- **Pool cap ≥ 6 failing on every third repeat (product, [OME-809](/OME/issues/OME-809)).** A slot timeline showed all 10 lines in the chat log but only the five "line two" bubbles.
  - Cause: `state.ts` keeps one bubble per member, and the stage floats what it finds at render time. When a speaker's two lines land in one frame, the first never floats.
  - The same cause made the existing `bubbles.e2e.ts:102` ("a third line sends the oldest away") go red once, showing `["one", "three"]`.
  - A deterministic repro (the watcher's rAF delayed 300 ms) is pinned as `test.fail` and failed 5/5. The cap test now spaces each speaker's lines 150 ms apart.
