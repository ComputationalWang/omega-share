
## Ports and leftover servers: automatic per agent (OME-821)
Don't export `OMEGA_*_PORT` or hand-pick ports. Each agent's runs bind a block of their own from `PAPERCLIP_AGENT_ID` (`e2e/support/ports.ts`; no agent id = slot 0 = 4400/5173/8787, as in CI). Every server the harness or a spec starts goes through `e2e/support/serve.ts`, which writes `$XDG_RUNTIME_DIR/omega-e2e-owners/<port>.json` and dies with the run (SIGTERM, a failure, or the runner being killed). A server already on a port is reused only if its owner file names you at HEAD. Anything else fails the run with the owner's name: someone else's → leave it; yours from another commit → `bun run e2e:reap` (stops only your own, by owner file); "no owner file" → a stray process, find it with `ss -ltnp`. Never `pkill -f`. `OMEGA_PORT_SLOT=<n>` pins a slot; an `OMEGA_*_PORT` still overrides one port (the perf runner pins 4470/5243/8857).

## Perf: submit, end the run, read the result next wake (OME-819)
Never `sleep`/poll for perf and no `flock … bun run perf`. `bun run perf:submit --issue OME-n [perf/x.perf.ts …]` queues the committed HEAD and returns at once; end the run; on the next heartbeat `bun run perf:result <job>` (exit 2 = still running: end the run again). Details: `docs/ops/perf-runner.md`.
